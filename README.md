# Сходка

Агент-редактор для Telegram-канала про культуру, моду, музыку, кино, архитектуру
и немного спорт. Сам следит за источниками, сверяет факты, пишет черновики постов
и присылает их в Telegram. Публикует человек — агент только готовит.

## Как работает

```
ленты изданий  →  Item  →  Story  →  Draft  →  Telegram
   RSS            сырьё   инфоповод  черновик   редактору
```

1. **Сбор.** Раз в час обходит 37 лент и складывает новые материалы. Повторы
   отсекаются по канонической ссылке (utm-метки срезаются).
2. **Группировка.** Модель склеивает материалы разных изданий про одно событие
   в один инфоповод, оценивает срочность (1–5) и важность (1–5) и отсеивает то,
   что каналу не подходит.
3. **Проверка.** Считает **код, а не модель**: новость подтверждена, если о ней
   написало авторитетное издание (tier 1) либо два разных профильных (tier 2).
   Одного профильного источника недостаточно.
4. **Черновик.** Текст пишется строго по собранным материалам — придумывать факты
   модели запрещено. Плюс подбирается фото.
5. **Отправка.** Готовый текст + служебный блок: категория, важность, источники,
   статус проверки.

### Что приходит и когда

| Что | Когда | Вид |
|---|---|---|
| Срочное (срочность ≥4) | сразу, в течение часа | готовый черновик |
| Обычное | 3 раза в день: 9:00, 15:00, 20:00 МСК | план публикаций + пачка черновиков |
| Громкое, но на одном источнике | вместе с остальным | ⚠️ сигнал **без готового текста** |

Последнее — намеренно. Пока новость держится на одном источнике, готовый текст
не пишется: это подталкивало бы опубликовать непроверенное. Приходят факт и
ссылки, решение принимает человек. Если новость подтвердят другие издания,
она придёт нормальным черновиком.

## Запуск

```bash
npm install
cp .env.example .env     # заполнить ключи
npx prisma db push       # создать таблицы
npm run seed             # залить список источников
npm run collect          # разовый сбор
npm run digest           # разовая подборка черновиков
```

## Переменные окружения

| Переменная | Обязательна | Зачем |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | бот, который шлёт черновики |
| `TELEGRAM_EDITOR_CHAT_ID` | да | куда слать (личка или служебный канал) |
| `DATABASE_URL` | да | Neon Postgres |
| `GOOGLE_GENAI_API_KEY` | да* | Gemini — основная модель |
| `GROQ_API_KEY` | да* | Groq — запасная, когда у Gemini кончается квота |
| `UNSPLASH_ACCESS_KEY` | нет | сток, если своего фото нет |
| `PEXELS_API_KEY` | нет | второй сток |

\* нужен хотя бы один из двух, но лучше оба: бесплатная квота Gemini на почасовом
кроне заканчивается регулярно, и тогда работу подхватывает Groq.

## Автозапуск

Крутится в GitHub Actions, сервер не нужен:

- `.github/workflows/collect.yml` — каждый час
- `.github/workflows/digest.yml` — три раза в день

Ключи живут в Settings → Secrets and variables → Actions.

Пайплайн специально не в Vercel: сбор с генерацией текстов занимает минуты,
а бесплатные функции Vercel обрываются через 10–60 секунд. Vercel остаётся
под будущий сайт-афишу, база у них будет общая.

## Источники

37 проверенных лент в [`src/lib/sources.ts`](src/lib/sources.ts). У каждой есть
`tier` (насколько можно верить в одиночку) и `weight` (насколько охотно берём
темы). У спорта вес занижен намеренно — его в канале должно быть мало.

После правки списка:

```bash
npm run check-feeds   # проверить, что ленты живы
npm run seed          # залить изменения в базу
```

Издания периодически выключают RSS. В том же файле внизу лежит `REJECTED_SOURCES`
— список тех, кого пробовали подключить и почему не вышло, чтобы не проверять
их заново каждые пару месяцев.

## Ограничения, из которых выросла эта конструкция

Многое в коде выглядит переусложнённым, пока не знаешь, обо что споткнулись.

**У бесплатного Groq лимит 8000 токенов в минуту.** Это главное ограничение
всего проекта. Из него следует почти вся остальная конструкция: пачки по 18
материалов, пауза 13 секунд между обращениями, потолок 80 материалов за запуск,
передача в модель только заголовков без описаний и дешёвый отсев в
[`prefilter.ts`](src/lib/prefilter.ts) до всякой модели. Если поднять размер
пачки — запуск начнёт падать с ошибкой 413.

**Общие ленты огромны.** У Коммерсанта в выдаче 705 записей, у ТАСС — 100.
Без ограничения `MAX_ITEMS_PER_SOURCE` одна такая лента вытесняет из разбора
всё остальное.

**Модель молча теряет часть материалов.** В первом же прогоне 699 из 728 штук
зависли неразобранными и уходили в модель каждый час заново. Теперь всё, что
модель не отнесла ни к одному сюжету, помечается разобранным принудительно.

**Строгий JSON-режим Groq ломается на длинных ответах** — отдаёт пустоту с
ошибкой валидации. Поэтому есть запасной путь через свободный режим.

**Спорт вытесняет остальное.** Матчи идут каждый день, а показы и релизы нет,
поэтому спортивные ленты забивали выдачу. Отсюда квота `SPORT_LIMIT` и
заниженные веса спортивных источников.

**Модель дописывает рекламу в конце.** Почти в каждом черновике появлялось
предложение о том, кому вещь «предназначена» и что надо «успеть купить».
Это же место — главный источник выдумок: там она сочинила, что вещи доступны
«только в цифровом виде», хотя они продавались в обычных магазинах.
Ловится в [`quality.ts`](src/lib/quality.ts), промтом надёжно не лечится.

## Настройка под себя

- **Тон текстов** — [`src/lib/style.ts`](src/lib/style.ts). Там же примеры нужного
  звучания: если черновики выходят не такими, правь в первую очередь их.
- **Сколько материалов в подборке, пороги срочности** — константы в начале
  [`src/pipeline/run.ts`](src/pipeline/run.ts).
- **Что считать подтверждённым** — `applyConfidence` в
  [`src/lib/cluster.ts`](src/lib/cluster.ts).
